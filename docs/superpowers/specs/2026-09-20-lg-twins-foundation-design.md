# LG 트윈스 팬사이트 — 0단계 기반 세팅 설계

작성일: 2026-09-20

## 1. 목표

비공식 LG 트윈스 팬사이트를 만든다. 전체 프로젝트는 하위 프로젝트로 쪼개서 각각 설계 → 구현한다. 이 문서는 **0단계(기반 세팅 + 메인 페이지)** 범위만 다룬다.

### 전체 로드맵 (순서 확정)

0. 기반 세팅 + 메인 페이지 (이 문서)
1. 역사/우승 기록 (정적)
2. 선수단 소개 (정적 데이터)
3. 응원가/응원 문화 (정적)
4. 경기 일정/결과 (데이터 소스 결정 필요)
5. 순위/기록 (4번과 같은 데이터 소스)
6. 뉴스/게시판 커뮤니티 (Supabase + RLS)

## 2. 확정된 결정

| 항목 | 결정 |
|------|------|
| 성격 | 비공식 팬사이트 |
| 스택 | Next.js (App Router) + TypeScript + GSAP |
| 디자인 | 다크 & 볼드. 배경은 순검정 대신 차콜(#16161a 안팎), 포인트 레드 #C30452 |
| 데이터 | 정적 TS 데이터 + 접근 함수 레이어 분리 (접근 A) |
| 배포 | Vercel 기준, Netlify도 가능한 정적 친화 구성 |
| 폴더 구조 | pixelconnect-standards 스킬로 세팅 (CLAUDE.md / .claude / src / tests / docs) |

## 3. 구조

```
src/
  app/
    layout.tsx        # 공통 레이아웃 (헤더/푸터, 폰트, 테마)
    page.tsx          # 메인 (섹션 조립만)
    (이후 단계) history/ players/ cheer/ schedule/ standings/ community/
  components/
    layout/           # Header, Footer
    home/             # Hero, NextGame, Summary, StarPlayers, HistoryPreview
    ui/               # Button, Card, SectionTitle
  data/               # 정적 데이터 (players.ts, history.ts ...)
  lib/                # 데이터 접근 함수, 애니메이션 훅
  styles/             # 디자인 토큰
tests/
docs/
```

### 핵심 규칙

- 페이지와 컴포넌트는 `data/`를 직접 import하지 않는다. `lib/`의 함수만 쓴다. 이후 외부 API나 Supabase로 바꿀 때 `lib/` 내부만 수정한다.
- 메인 섹션은 `components/home/` 아래 독립 컴포넌트로 만든다.
- 테마 컬러는 CSS 변수(디자인 토큰) 한 곳에서 관리한다.
- GSAP은 클라이언트 컴포넌트 안에서만 쓰고, 애니메이션 로직은 `lib/`의 훅으로 분리한다. `prefers-reduced-motion`을 지킨다.

## 4. 메인 페이지 섹션

| # | 섹션 | 내용 | 데이터 함수 |
|---|------|------|-------------|
| 1 | Hero | "WE ARE TWINS." 큰 타이포, 레드 원형 포인트, GSAP 텍스트 리빌. CTA 2개(일정 보기, 선수단 보기) | 없음 |
| 2 | NextGame | 상대팀, 날짜, 구장, 카운트다운(일/시/분/초) | `getNextGame()` (더미) |
| 3 | Summary | 최근 5경기 승/패 칩, 현재 순위, 승-패-무 | `getRecentGames()`, `getStandingSummary()` (더미) |
| 4 | StarPlayers | 선수 카드 3~4개, 호버 시 살짝 올라오는 효과 | `getStarPlayers()` (정적) |
| 5 | HistoryPreview | 우승 연도 타임라인, 스크롤 등장, "전체 역사 보기" 링크 | `getChampionships()` (정적) |
| 6 | Footer | 비공식 팬사이트 고지, 메뉴 링크, 저작권 안내 | 없음 |

**Header**: 텍스트 로고(LG TWINS), 메뉴(일정·선수단·역사·응원·순위·커뮤니티), 모바일은 햄버거. 아직 없는 페이지는 "준비 중" 처리.

### 더미 데이터 원칙

- 더미는 `data/`에 두고 `lib/` 함수가 반환한다. 4~5단계에서 실제 데이터로 교체해도 화면 코드는 그대로다.
- 더미 값은 코드 주석으로 명시해 실제 데이터와 혼동되지 않게 한다.
- 사실 정보(우승 연도 등)는 확실한 것만 넣는다. 불확실한 것은 "확인 필요"로 표시하고 넣지 않는다.

### 반응형

모바일 우선. Summary와 StarPlayers는 모바일에서 세로 스택 또는 가로 스크롤.

## 5. 에러 처리

- 데이터 함수가 실패하거나 비어 있으면 해당 섹션만 숨기거나 빈 상태 UI를 보여준다. 페이지 전체는 깨지지 않는다.
- 카운트다운은 경기 시간이 지나면 "경기 진행 중/종료" 상태로 전환한다.
- 없는 페이지는 커스텀 404와 "준비 중" 안내를 쓴다.

## 6. 접근성 / 성능 / SEO

- 시맨틱 태그(header/nav/main/section), 이미지 alt, 포커스 링 유지.
- 다크 배경 위 텍스트 대비 4.5:1 이상. 레드 텍스트는 큰 글씨에만 사용.
- `prefers-reduced-motion`이면 GSAP 애니메이션을 끄고 정적으로 표시.
- `next/image`, `next/font` 사용. GSAP은 필요한 컴포넌트에서만 로드.
- 목표: Lighthouse 성능/접근성 90+.
- 메타데이터, OG 이미지, sitemap, robots 기본 포함. 상세 SEO는 이후 `fire-your-seo-agency` 스킬로 진행 가능.

## 7. 테스트

- 단위(Vitest): `lib/` 데이터 함수, 카운트다운 계산 로직.
- 컴포넌트: 로딩/빈 상태/정상 상태 렌더링.
- 시각 확인: 구현 후 dev 서버를 띄워 브라우저로 직접 확인.

## 8. 법적 / 저작권

- 구단 공식 로고와 선수 사진은 사용하지 않는다. 텍스트, 컬러, 자체 제작 그래픽만 사용한다.
- 푸터에 "비공식 팬사이트이며 LG 트윈스와 무관하다"는 문구를 넣는다.

## 9. 배포

Vercel 기준. `.env`는 0단계에서 필요 없다. Supabase는 6단계에서 도입한다.

## 10. 범위 밖 (0단계에서 하지 않는 것)

- 실제 경기/순위 데이터 연동 (4~5단계)
- 개별 페이지 콘텐츠 (1~3단계)
- 로그인, 게시판, DB (6단계)
