# LG 트윈스 팬사이트 — 2단계 선수단 소개 페이지 설계

작성일: 2026-09-25

## 1. 목표

로드맵 2단계인 **선수단 소개 페이지(`/players`)**를 만든다. 포지션 탭으로 74명 전체 등록 선수를 보여주고, 선수 카드를 클릭하면 간단한 개인 상세 페이지(`/players/[name]`)로 이동한다.

### 전체 로드맵에서의 위치

0. 기반 세팅 + 메인 페이지 (완료)
1. 역사/우승 기록 (완료)
2. **선수단 소개 (이 문서)**
3. 응원가/응원 문화
4. 경기 일정/결과
5. 순위/기록
6. 뉴스/게시판 커뮤니티

## 2. 확정된 결정

| 항목 | 결정 |

| 로스터 범위 | 정규 등록 선수만 74명 (투수 42, 포수 7, 내야수 15, 외야수 10). 육성선수(39명)는 제외 |

| URL 슬러그 | 선수 이름을 그대로 사용 (`/players/오지환`). 74명 중 이름 중복 없음을 확인했음 |

| 사진 | 사용하지 않는다(기존 규칙 유지). 이니셜 원 + 큰 번호로 대체 |

## 4. 데이터 모델

```ts
// src/lib/types.ts
export type PlayerPosition = "투수" | "포수" | "내야수" | "외야수";

export type Player = {
  name: string;
  number: string | null; // 등번호. 미정인 경우 null
  position: PlayerPosition;
};
```

- `src/data/players.ts`의 `ALL_PLAYERS: Player[]`에 위 74명을 전부 담는다.
- `src/lib/players.ts`의 `getPlayers(): Promise<Player[]>`가 유일한 접근 창구다.
- 메인 페이지의 `getStarPlayers()`(기존 오지환/문보경/박동원/임찬규 4명)는 `getPlayers()`가 반환하는 74명 중 이 4명을 필터링해 파생시키도록 리팩터링한다. 데이터가 두 곳에서 따로 관리되지 않게 한다.

## 5. 페이지 구조

```
src/app/players/
  page.tsx              # /players — 탭 필터 + 카드 그리드
  [name]/
    page.tsx              # /players/[name] — 개인 상세
src/components/players/
  PositionTabs.tsx        # 단일 선택 탭 (전체/투수/포수/내야수/외야수)
  PositionTabs.module.css
  PlayerCard.tsx           # 이니셜 원 + 큰 번호 + 이름 + 포지션, 상세 페이지로 링크
  PlayerCard.module.css
  PlayerGrid.tsx           # 탭 상태 보유, PositionTabs + 카드 그리드 조합
```

- **목록 페이지**: `PositionTabs`는 1단계의 `CategoryFilter`와 같은 `aria-pressed` 버튼 그룹 패턴을 재사용한다(일관성 유지). 기본 선택은 "전체".
- **카드**: 사진 대신 이름 첫 글자를 넣은 원형 아바타(레드 배경), 큰 번호(display 폰트, 레드 계열), 이름, 포지션. 번호가 없는 선수는 "미정"을 표시한다. 카드 전체가 `/players/{이름}`으로 연결된 링크다.
- **상세 페이지**: 이름을 동적 라우트 파라미터로 받아 `getPlayers()`에서 일치하는 선수를 찾는다. 없으면 Next.js `notFound()`를 호출해 기존 전역 404 페이지("준비 중이에요")로 보낸다. 상세 페이지에는 큰 번호, 이름, 포지션, "선수단으로" 돌아가는 링크만 넣는다.
- **반응형**: 카드 그리드는 데스크톱 4~5열, 모바일 2열.

## 6. 접근성, 메타데이터, 에러 처리

- `PositionTabs`는 1단계 `CategoryFilter`와 동일하게 `role="group"`, 각 버튼 `aria-pressed`, 네이티브 `<button>`으로 키보드 조작이 자동으로 된다.
- `/players` 메타데이터: title "선수단", description은 74명 로스터를 소개하는 한 줄.
- `/players/[name]` 메타데이터: `generateMetadata`로 `title: "{이름} | 선수단"` 동적 생성. 없는 이름이면 `notFound()`가 먼저 발생하므로 메타데이터도 자연히 생성되지 않는다.
- **데이터 실패 격리**: `getPlayers()` 실패 시 `/players` 목록 페이지는 크래시 대신 "선수단 정보를 불러오지 못했어요" 문구를 보여준다(`safe()` 재사용). 메인 페이지의 `getStarPlayers()`도 같은 원본 함수에서 파생되므로, 1단계 역사 페이지 때와 마찬가지로 원본 데이터 실패 시 메인 페이지의 스타 플레이어 섹션도 함께 조용히 사라진다(기존 설계와 일관됨, 새로운 문제 아님).
- **저작권**: 선수 사진은 쓰지 않는다. 실명은 텍스트로만 사용한다(공식 등록 정보, 사실 정보 표기이므로 문제 없음).

## 7. 테스트

- **단위(Vitest)**: `lib/players.ts`의 `getPlayers()`(74명 반환, 포지션별 개수 검증)와 `getStarPlayers()`(4명, 74명의 부분집합인지 검증).
- **컴포넌트**: `PlayerCard`(번호/미정 표시, 이름·포지션 렌더링, 링크 href), `PositionTabs`(전체 포함 5개 탭, aria-pressed, 클릭 시 onSelect 호출 — 1단계 `CategoryFilter` 테스트와 유사한 구조), `PlayerGrid`(기본 전체 표시, 탭 클릭 시 필터링). 74명 전체를 테스트에 하드코딩하지 않고, 더미 3~4명 배열로 컴포넌트 로직만 검증한다.
- **상세 페이지**: 존재하는 이름으로 접근 시 정보가 보이는지, 존재하지 않는 이름으로 접근 시 404로 가는지는 구현 후 브라우저로 확인한다(1단계와 같은 패턴 — `page.tsx` 자체는 비동기 서버 컴포넌트라 별도 유닛 테스트를 두지 않는다).

## 8. 범위 밖 (2단계에서 하지 않는 것)

- 선수 사진
- 시즌 기록·스탯 (5단계 순위/기록에서 다룬다)
- 감독·코치 정보 (선수만 다룬다)
- 육성선수 39명 (필요해지면 별도로 검토)
